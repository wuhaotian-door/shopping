# 添加日志系统

## 目标
为 ai-server 项目添加结构化日志系统，替换现有的 `print()` 调试输出，方便开发调试和线上排查。

## 当前状态
- 项目使用 `print()` 做调试输出，分散在 6 个文件中
- 无时间戳、无日志级别、无文件持久化
- `logs/` 目录已存在但未被有效使用

## 步骤

### 步骤 1: 创建集中式日志模块 `logger_config.py`
- 使用 Python `logging` 标准库
- 配置双重输出：控制台（带颜色）+ 文件（带轮转）
- 提供 `get_logger(name)` 工厂函数
- 格式：`时间 | 级别 | 模块:函数:行号 | 消息`

### 步骤 2: 添加请求追踪中间件
- 在 `main.py` 中添加中间件，为每个请求生成唯一 request_id
- 将 request_id 注入日志上下文

### 步骤 3: 替换所有 `print()` 为 `logger` 调用
- `agent_human.py`: 7 处 print
- `agent_multi.py`: 3 处 print
- `agent_subgraph.py`: 8 处 print
- `agent_advanced.py`: 13 处 print
- `rag.py`: 6 处 print
- `production.py`: 2 处 print

### 步骤 4: 为关键 API 端点添加请求日志
- 记录每个 API 请求的进入/离开
- 记录耗时

### 步骤 5: 验证
- 确保项目能正常启动
- 检查日志输出格式

## 影响范围
- 新增: `logger_config.py`
- 修改: `main.py`, `agent_human.py`, `agent_multi.py`, `agent_subgraph.py`, `agent_advanced.py`, `rag.py`, `production.py`

## 状态
已完成

## 变更总结
- 新增 `logger_config.py`: 集中式日志模块，支持控制台+文件双输出、RotatingFileHandler 自动轮转
- 新增请求追踪中间件: 每个 HTTP 请求自动生成 request_id，记录进入/离开和耗时
- 替换 6 个文件中全部 ~40 处 `print()` 为结构化 `logger` 调用
- 10 个模块通过语法检查，日志系统初始化验证通过
