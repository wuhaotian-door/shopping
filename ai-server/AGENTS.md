\# AGENTS.md



\# 项目指南



\## 0. 最高优先级 — 不可跳过



> **本节约定了 Claude Code 的行为底线。违反本节任何一条 = Claude Code 执行失败。**



\### 0.1 执行计划硬性前置条件



**Claude Code 不得在没有执行计划的情况下调用任何写操作工具（Write、Edit、Bash 写操作）。**



每次响应中调用写工具前，Claude Code 必须完成以下自检，全部通过才允许执行：



| # | 检查项 | 通过条件 | 未通过的后果 |
|---|--------|----------|--------------|
| 1 | 任务已识别 | 能一句话描述本次要完成什么 | 先明确任务，禁止模糊执行 |
| 2 | active 计划已创建 | `docs/exec-plans/active/` 下存在本次任务的 `.md` 文件 | **立即创建计划，然后才能调用写工具** |
| 3 | 计划与当前操作一致 | 计划文档中已列出当前操作的步骤 | 先更新计划文档 |



**没有计划文档 = 没有工具调用。没有任何例外。**



纯只读操作（Read、Glob、Grep、Bash --version/list/read 类）不受此限制 — 读操作是制定计划的前提。



\### 0.2 回答边界规则



**Claude Code 的每一次回答必须严格限定在当前任务范围内。任务的边界由 active 计划文档定义。**



回答结构强制要求：



1. **开头** — 确认 active 计划已存在，一句话说明本步执行计划中的哪个步骤

2. **主体** — 执行任务，输出结果

3. **结尾** — 确认本步完成，更新计划状态。**到此为止，不附加任何其他内容。**



严格禁止以下结尾行为：



\* "需要我继续吗？"

\* "下一步你想做什么？"

\* "你觉得这个方向对吗？"

\* "要不要我帮你...？"

\* "需要我确认...吗？"

\* 任何形式的建议、反问、引导下一个任务



**任务完成 = 回答结束。没有例外。**



如果用户给出了新任务，那是下一轮对话的事。Claude Code 不得在当前回答中预判、引导或建议下一个任务。



\### 0.3 AGENTS.md 与 CLAUDE.md 一致性



**`AGENTS.md` 和 `CLAUDE.md` 是同一个文件的两份副本，内容必须时刻保持一致。**



修改其中任何一个后，必须立即将完全相同的内容复制到另一个。两者不存在主次关系 — 修改即同步。



Claude Code 每次读取 CLAUDE.md 时，实际上读到的就是 AGENTS.md 的内容。两者不一致 = 规则冲突 = Claude Code 行为不可预期。



\### 0.4 知识来源准则



**本项目不使用 Claude Code 自带的记忆系统（memory/ 目录）。**



唯一的例外：当前 session 中的历史对话（上下文中的对话记录）可以正常使用。



所有项目知识、规则、设计决策、执行计划，必须以本文档体系为唯一依据：



\```text

AGENTS.md → 核心文档 → docs/ 子目录 → 具体文档

\```



\### 为什么



\* 文档体系受版本控制（Git），可以随代码一起演进

\* Claude Code memory 是独立于仓库的本地文件，无法被团队共享

\* 文档体系支持索引分层加载，避免上下文污染

\* 单一知识来源避免 memory 与文档不一致导致的决策冲突



\### 0.5 执行计划同步规则



**Claude Code 执行的每一个动作，都视为计划或计划的一部分。**



无论任务大小，Claude Code 必须：



1\. **执行前** — 在 `docs/exec-plans/active/` 中创建或更新执行计划文档

2\. **执行中** — 当实际执行偏离计划时，同步更新计划文档

3\. **执行后** — 将完成的计划迁移至 `docs/exec-plans/completed/`

这包括但不限于：



\* 创建新文件

\* 修改现有代码

\* 重构

\* 修复 Bug

\* 更新文档

\* 变更架构或设计决策



\### 0.6 执行计划文档命名规范



\```text

docs/exec-plans/active/<YYYY-MM-DD>-<简短描述>.md

\```



示例：



\```text

docs/exec-plans/active/2026-07-23-ai-rag-问答接口.md

docs/exec-plans/active/2026-07-23-文档体系搭建.md

\```



\### 0.7 计划文档最小内容



每个执行计划文档至少包含：



\* 目标：要完成什么

\* 步骤：拆解为具体步骤

\* 影响范围：涉及哪些文件/模块

\* 状态：进行中 / 已完成



\### 0.8 产品需求与技术设计分离



**产品需求文档和技术设计文档有严格边界，不得混淆。**



| | 产品需求文档 | 技术设计文档 |
|---|------------|------------|
| 存放位置 | `docs/product-specs/` | `docs/design-docs/` |
| 回答的问题 | 用户要什么 | 怎么实现 |
| 内容 | 用户场景、使用流程、验收标准 | 技术方案、架构决策、实现权衡 |
| 禁止出现 | 数据库名、API 框架、向量库、LLM 名称、具体算法 | — |
| 谁是输入 | 需求是设计的输入 | 设计是编码的输入 |



**Claude Code 编写需求文档时，不得写入任何技术实现细节。** 技术方案在设计阶段制定，不在需求阶段预设。

\## 1. 文件定位



本项目采用 \*\*Harness Engineering 文档架构\*\*。



该架构用于帮助 Claude Code 理解、开发和维护复杂软件系统。



项目不仅由代码组成，还包含：



\* 产品知识

\* 架构知识

\* 设计决策

\* 执行计划

\* 技术约束

\* 工程质量要求



本文件是 Claude Code 的\*\*项目知识入口\*\*。



它不负责存储所有项目细节。



它只负责：



\* 解释项目文档结构

\* 指导 Claude Code 查找信息

\* 定义文档之间的关系

\* 指导上下文加载流程



具体规则、设计方案、产品需求应存放在对应文档中。

\# 5. Index索引机制



\## 5.1 索引作用



每个文档目录下的 `index.md` 是\*\*给 Claude Code 的使用说明\*\*。



它的职责：



\* 告诉 AI 这个目录里的文档是干什么的

\* 告诉 AI 什么时候、怎么使用这些文档

\* 描述文档的组织逻辑和查找策略



它不负责：



\* 列出具体文件名

\* 维护文件清单

\* 包含实际的计划/需求/设计内容



Claude Code 通过 index.md 理解该领域的文档结构后，自行导航到具体文档。



访问路径：



```text

AGENTS.md



↓



领域index.md（理解文档用途和使用方式）



↓



AI 自行定位并读取具体文档



↓



代码实现

```



\---



\## 5.2 Claude Code 禁止行为



禁止：



直接扫描整个docs目录。



错误方式：



```text

读取全部Markdown



↓



消耗大量上下文



↓



无法判断重点

```



正确方式：



```text

定位任务类型



↓



读取对应index.md



↓



加载相关文档

```

\# 9. 核心理念



本项目不是简单的代码仓库。



它是一个：



> 可被人类和 Claude Code 共同理解、维护和演进的软件工程知识系统。



代码描述：



> 当前系统如何运行。



文档描述：



> 为什么这样设计，以及未来如何继续发展。



Claude Code 在修改代码前，必须优先建立正确的项目上下文。



先理解，再行动。
